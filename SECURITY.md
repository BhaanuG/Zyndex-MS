## 2. Platform Security Architecture & Controls

Zyndex incorporates enterprise security controls enforced end-to-end:

### 2.1 Multi-Factor & Dynamic Authentication
- **Dynamic 4-Digit Numeric OTP**: Generated via cryptographically secure random number generator (`java.security.SecureRandom`) and dispatched via TLS-encrypted SMTP relay with 2-minute expiration and maximum 5-attempt brute-force protection.
- **24-Hour Trusted Device Authorization**: Device fingerprints and random tokens allow verified users to bypass repetitive OTP checks for exactly 24 hours on the same machine while strictly maintaining visual CAPTCHA verification.
- **Session Timeout Protection**: Inactivity tracking terminates sessions after 2 hours and 30 minutes, prompting an interactive warning dialogue at the 2-hour mark to preserve session state.
- **BCrypt Password Hashing**: Passwords require mixed case, numerical digits, and special characters, hashed using `BCryptPasswordEncoder` with salt rounds prior to persistence.

### 2.2 JWT & Inter-Service Boundary Security
- **HMAC-SHA256 Signed JWTs**: Generated by `auth-service` and verified statelessly by `api-gateway` on all protected routes (`/api/resources/**`, `/api/usage/**`, `/api/subscriptions/**`, `/api/users/**`).
- **Internal Microservice Header Verification**: Downstream microservices enforce a shared `X-Gateway-Secret` via `GatewaySecretFilter`, immediately rejecting direct non-gateway traffic.
- **Role-Based Access Governance (RBAC)**: Strict role separation isolating `Main Admin` (`Bhaanugali@gmail.com`), regular `Admin`, and `User` entitlements. Sensitive administrative endpoints (`/api/usage/engagement/analytics`, `/api/subscriptions/admin/**`, `/api/users/export`) strictly enforce primary administrative credentials.

### 2.3 Data Protection & Payment Reconciliation
- **Dynamic In-Memory PDF Slicing**: Free and evaluation users are restricted to 10-page document previews sliced in-memory via Apache PDFBox, preventing unauthorized retrieval of complete files.
- **UPI QR Direct Settlement**: Payment flows eliminate recurring card credentials from client storage. All transactions verify 12-digit bank UTRs with state transition logging and admin audit histories.

## 3. Reporting a Vulnerability

If you identify a potential security vulnerability in Zyndex, please notify us through our dedicated private reporting channels. **Do not create public GitHub issues or discussions for undisclosed security vulnerabilities.**

### Private Reporting Channels
Please send detailed reports to our security contacts:
- **Primary Lead**: `Bhaanugali@gmail.com`
- **Institutional Contact**: `2400030952@kluniversity.in`

### Report Format
To help us triage and resolve the issue quickly, please include:
1. **Affected Subsystem**: Specify whether the vulnerability affects the frontend web client, `api-gateway`, `auth-service`, `content-service`, `access-service`, `usage-service`, or `subscription-service`.
2. **Vulnerability Type**: e.g., Authentication Bypass, Insecure Direct Object Reference (IDOR), SQL Injection, Cross-Site Scripting (XSS), Sensitive Data Exposure, Privilege Escalation.
3. **Step-by-Step Reproduction**: Detailed steps, cURL requests, or proof of concept (PoC) illustrating the issue.
4. **Estimated Impact**: An assessment of potential risk to user accounts, proprietary academic content, or system availability.

## 4. Response Timeframes & Disclosure Process

- **Initial Acknowledgment**: Within **24 hours** of submission.
- **Vulnerability Assessment & Triaging**: Within **48 to 72 hours**.
- **Remediation & Patch Deployment**: Critical severity vulnerabilities are prioritized for hotfix deployment within **3 to 7 business days**.
- **Coordinated Disclosure**: We ask researchers and contributors to maintain confidentiality until security updates are pushed to `origin/main` and verified. Full credit will be attributed in release notes.
