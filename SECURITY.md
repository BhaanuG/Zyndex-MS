# Security Policy

## Supported Versions

We provide security updates and patches for the current release series of **Zyndex**:

| Version | Supported          | Status |
| ------- | ------------------ | ------ |
| 1.0.x   | :white_check_mark: | Active production release |
| < 1.0   | :x:                | Legacy / deprecated |

---

## Reporting a Vulnerability

The Zyndex team takes academic data privacy, authentication integrity, and intellectual property protection seriously.

If you believe you have found a security vulnerability in Zyndex (including authentication bypass, privilege escalation, JWT leakage, SQL injection, or unauthenticated file access), please **do not open a public GitHub issue**.

### Reporting Channel
- Please send an encrypted or direct email report to:  
  **`Bhaanugali@gmail.com`** and **`2400030952@kluniversity.in`**
- Include:
  - Description of the vulnerability and affected microservice (e.g. `auth-service`, `api-gateway`, `content-service`, `access-service`).
  - Step-by-step reproduction guide or Proof of Concept (PoC).
  - Assessment of impact (e.g. user account compromise, unauthorized document access).
  - Your name or handle for public acknowledgement upon release.

### Response Time & Disclosure
- **Initial Response**: Within 24-48 hours with acknowledgment.
- **Triage & Fix**: We will investigate and provide regular status updates.
- **Responsible Disclosure**: We request that you maintain confidentiality until a patch has been merged and deployed.
